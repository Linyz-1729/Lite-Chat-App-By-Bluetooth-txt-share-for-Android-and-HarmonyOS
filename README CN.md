# 蓝易聊 · Bluetooth Easy Talk

**每一条消息都是一个真正的 `.txt` 文件，通过蓝牙从一个手机送到另一个手机。**

没有服务器，没有账号，没有云端。只有文件在两个手机之间流动。

## 核心理念

这个应用里没有任何数据库。聊天记录，就是两个普通文件夹的内容：

```
<应用目录>/txtchat/
├── outbox/    我发出去的每一条消息，各占一个 .txt 文件
├── inbox/     收到的每一条消息，各占一个 .txt 文件
└── *.txt      导出的整段对话记录
```

**文件名 = 元数据，文件内容 = 消息正文。**

```
outbox/20240601-120430_我的手机.txt    内容：晚上七点在地铁站见
inbox/20240601-120502_小明.txt         内容：好的，我提前十分钟到
```

所以：

- 任何一个 `.txt` 都能用记事本打开，**不需要安装这个应用**
- 删掉一个文件就等于删掉一条消息，没有隐藏数据
- 收到的文件与发出去的文件**逐字节完全相同**

## 逐条特点

### 01 —— 每一条消息，都是一个真实的 `.txt` 文件

- 发消息时，应用先把内容写成一个纯文本文件，再把**这个文件本身**通过蓝牙推出去。
- 收到的副本与发出的原件逐字节一致：没有被改写、没有被压缩、没有被装进任何容器。
- 任何文本编辑器都能打开它。想读自己的历史记录，甚至可以不用这个应用。

### 02 —— 聊天记录，就是两个文件夹

- `outbox/` 装着你发出去的，`inbox/` 装着收到的。一个文件就是一条消息。
- 不需要「导出聊天记录」这一步，因为记录本来就在一个你能打开的文件夹里。
- 在文件管理器里删掉一个 `.txt`，聊天里那条消息就消失了，没有任何隐藏状态。

### 03 —— 蓝牙直连，根本没有联网能力

- 应用**从未申请 INTERNET 权限**。这不是「我们承诺不上传」，而是系统层面它根本连不上网络。
- 没有账号、没有注册、没有服务器、没有云端同步、没有埋点。
- 数据只存在于两台已配对手机之间的一条蓝牙链路上。
- 飞行模式下照样能用。

### 04 —— 一套为 `.txt` 设计的传输协议

- 走标准蓝牙串口（RFCOMM / SPP），服务 UUID `00001101-0000-1000-8000-00805F9B34FB`。
- 一条消息 = 一个帧：一行帧头（字节数 + 文件名），紧跟原始文件字节。
- 采用**长度前缀**分帧，因此正文里出现换行、出现空行、甚至正文本身长得像帧头，都不会破坏协议。
- 单条上限 256 KB；畸形帧头与被截断的帧会被明确拒绝，而不是悄悄出错。

### 05 —— 扁平设计，全应用零图标

- 界面里没有任何图标。所有「按钮」都是文字，靠强调色和字重区分。
- 消息气泡是纯色圆角长方形：没有阴影、没有渐变、没有描边、没有水波纹。
- **安装包内图片资源数量为 0**（已实测）。整个界面由文字、色块和 1dp 细线构成。
- 连聊天背景图都不是随包发的，而是你运行时自己选的那一张。

### 06 —— 极致轻量

- 安装体积 **72.7 KB**，不到一张普通手机照片的十分之一。
- **零第三方依赖**：没有 AndroidX、没有 AppCompat、没有 Material、没有图片加载库、没有 JSON 库、没有混淆器。
- 16 个 Java 文件、约 3,072 行代码，短到可以从头读到尾。
- 后台驻留时内存占用极小，因为它本来就只做一件事：收文件、存文件。

### 07 —— 兼容 Android 4.0 及以上

- `minSdk 14`。2011 年的老机器和今天的新旗舰都能装。
- 刻意避开了新 API：不用 `setBackground`（16）、不用 `setShowWhen`（17），老系统上不会因为找不到方法而 `NoSuchMethodError` 崩溃。
- 通知构建在 Android 4.0 / 4.1 上会自动退回 API 16 之前的旧写法。
- 存储只用应用专属目录，所以在 Android 10 以上的新机型上，它**一个存储权限都不需要**。
- 签名同时包含 v1 + v2 + v3；其中 v1 的 JAR 签名正是 Android 4.x 能装的关键。

### 08 —— 暗色 / 浅色 / 跟随系统

- 设置页一键切换，立即生效，不用重启应用。
- 两套完整色板，共 8 个色彩槽位：背景、面板、正文、次要文字、强调色、发出气泡、收到气泡、分隔线。
- 暗色模式是手写的，没有交给 AppCompat —— 所以它在 **Android 4.0 上同样生效**，而不是像很多应用那样只有新系统才支持。

### 09 —— 四国语言

- **中文 · English · 日本語 · Русский**，应用内可切换，也可以跟随系统语言。
- **每种语言 92 条字符串**，四份翻译的键经过校验完全对齐，不会出现漏翻译而悄悄回退英文的情况。
- 语言名用各自的母语书写（中文 / English / 日本語 / Русский），看不懂当前界面也能找到自己的语言。
- 应用名本身也做了本地化：中文系统显示 **蓝易聊**，其他语言显示 **Bluetooth Easy Talk**。

### 10 —— 自定义聊天背景

- 可以选一张自己的图片铺在消息列表后面，也可以随时移除。
- 图片上自动盖一层当前主题背景色的 60% 蒙版，所以浅色主题配深色字、暗色主题配浅色字，都保持清晰可读。
- 有背景图时，消息气泡会自动变得略微透明，让图片透出来。
- 为老机器做了防护：两遍解码、按屏幕尺寸降采样、使用每像素 2 字节的 `RGB_565`、并捕获内存溢出 —— 在只有 16 MB 堆的手机上也不会崩溃。

### 11 —— 前台安静，后台可靠

- **你正在看聊天界面**时收到消息：不弹任何提示。消息直接出现在列表里并滚到底部 —— 你已经在看了，再弹一个纯属打扰。
- **你切到别的应用**时收到消息：发一条常规系统通知，标题是发送者名字，正文是消息内容，点一下回到聊天，可以滑动清除。
- 两类通知分属**两个独立渠道**，可以在系统设置里单独关掉其中一类。
- 开启「后台接收」后，应用会用前台服务把蓝牙链路保住，切到后台不会掉线。

### 12 —— 对方不装这个应用，也能收到

- 实时聊天需要两端都装。但另外两条路，对方装不装都无所谓：
- **「用蓝牙分享 .txt」**把对话或单条消息交给系统蓝牙（OBEX 对象推送），文件直接落进对方手机的蓝牙接收目录，对方用任何软件都能看。
- 别人用系统蓝牙发给你的 `.txt`，可以在文件管理器或通知栏里**「分享到 蓝易聊」**，自动导入成一条正常的聊天消息。
- 也就是说：这个应用既能当聊天工具，也能当一个「用蓝牙递纸条」的工具。

### 13 —— 不需要 Gradle 就能构建

- 构建脚本直接驱动 `aapt2 → javac → d8 → zipalign → apksigner` 这条经典流水线。不下载依赖，不起 Gradle 守护进程，不开 Android Studio。
- 工具链（JDK 17 + Android build-tools 34 + platform 34）由一个脚本一次性下载到仓库内的 `.tools/` 目录。
- 每次构建按版本号输出到 `releases/v<版本>/` 独立目录，历史版本永远不会被覆盖。

### 14 —— 传输协议是有单元测试的

- 编解码逻辑被刻意抽成一个不依赖 `android.*` 的类，因此**编进 APK 的就是测的那一份源码**，而不是复制出来的副本。测试在电脑的普通 JVM 上直接跑。
- **70 项断言全部通过**，覆盖：帧头解析、畸形帧拒绝、零长度文件、超长帧头、截断帧、文件名里的空格与下划线。
- 四种语言的发送者名往返一致，并验证文件名不会超出文件系统限制。
- 安全用例：路径穿越（`../../secret.txt`）、Windows 非法字符、控制字符、纯点号名，全部被安全降级处理。
- 还有一条完整链路回环测试：按发送端写法拼出一串帧，再按接收端写法读回来，逐条逐字节比对 —— 其中包含中日俄文、表情符号、多行正文，以及一条正文本身就冒充帧头的消息。

### 15 —— 几乎没有权限负担

- 没有 INTERNET、没有定位、没有通讯录、没有相机，新系统上也没有存储权限。
- Android 12 以上只申请两个蓝牙运行权限；旧版本用安装时授予的蓝牙权限，并在清单里标注了适用的最高版本。
- 通知权限只在你主动打开「后台接收」的那一刻才申请，不会一启动就反复打扰。
- 写外部存储的权限被限定在 Android 4.3 及以下，新机型完全用不到。

### 16 —— 整段对话可以导出成一个 `.txt`

- 设置页一键把 `inbox` 与 `outbox` 合并成一份带时间戳的对话记录。
- 导出结果本身就是纯文本：可以直接分享、打印、存档，或者再用蓝牙发出去。
- 导出的文件通过应用内置的只读内容提供者共享，在 Android 7 以上不会触发系统的文件 URI 泄露防护。

### 17 —— 打开应用，键盘已经在那儿

- 进入应用即聚焦输入框、唤出系统输入法，不用先点一下才能打第一个字。
- 实现方式是给窗口声明 `SOFT_INPUT_STATE_VISIBLE`，再在下一帧补一次焦点请求 —— 因为窗口还没真正拿到焦点时，`showSoftInput` 会被系统静默忽略。
- 窗口采用 `ADJUST_RESIZE`，键盘弹起时把消息列表顶上去，而不是把它盖住。

### 18 —— 发送消息不打断输入

- 消息发出后输入框被清空，但**焦点保留**、键盘保持展开 —— 可以直接接着打下一句，不必再点一次输入框。
- 发送按钮刻意设为不可获取焦点，点它永远不会把焦点从输入框抢走。
- 每次发送后还会再做一次兜底聚焦，因为部分厂商 ROM 在这件事上的行为和原生 Android 并不一致。

## 三种用法

**一、实时聊天** —— 两端都要装
两台手机先在系统蓝牙设置里配对一次。一端打开「设备 → 开始监听」；另一端打开「设备」，在已配对列表里点对方的名字。连上后直接打字发送。

**二、把 .txt 发给任何人** —— 对方不需要装
设置页 →「用蓝牙分享 .txt」→ 在系统分享面板里选蓝牙 → 选中对方设备。文件会进入对方手机的蓝牙接收目录。

**三、收下别人发来的 .txt** —— 对方不需要装
对方用系统蓝牙把 `.txt` 推给你。在通知栏或文件管理器里选择「分享到 蓝易聊」，它会自动导入成一条正常的聊天消息。

## 鸿蒙原生版 —— 开发状况说明

**一句话：源码已经写完，但还编译不过，目前处于停滞、等待解决的状态。**

这一节如实写出，而不是略过 —— 一份承诺了却拿不出来的产物，比一份直接说明卡在哪里的说明要糟得多。

### 已经完成的部分

- **工具链已验证可用。** DevEco Studio 26（HarmonyOS SDK 26.0.0 / API 26）、hvigor 6.26.8、Node 与 HAP 签名工具都已定位并从命令行驱动；一个空的鸿蒙工程已完整构建成功，产出了合法的 `entry-default-unsigned.hap`（45,688 字节）—— 说明整条流水线本身是通的。
- **14 个 ArkTS 源文件已全部写完，共 2,103 行**，架构与安卓版一一对应：长度前缀的 `.txt` 协议（`TxtCodec.ets`）、双文件夹存储（`ChatStore.ets`）、蓝牙 SPP 引擎（`ChatEngine.ets`），以及偏好设置、主题、自定义背景、权限助手和三个页面（聊天 / 设备 / 设置）。
- **协议互通是设计好的。** 两端用同一个标准 SPP UUID、同一套帧格式，因此鸿蒙版一旦编译通过，理论上可以直接和安卓版对聊。

### 卡住的地方

ArkTS 编译器不接受这个工程。错误数量已经从 **50 个压到 19 个、再到 11 个**，但剩下的仍未解决：

1. **还剩 11 个 ArkTS 编译错误**，全部属于同一类：*“Unable to resolve signature of property decorator when called as an expression”*。几乎可以确定是**一个根因在三个页面文件里级联放大**，而不是 11 个彼此独立的 bug。
2. **构建日志把诊断信息截断了。** `At File: …` 后缀被按固定宽度切掉，所以这些错误目前**不带文件名和行号** —— 每次尝试都更像在猜，而不是在修。
3. **签名是第二道独立的坎。** 零售鸿蒙手机不会安装用 SDK 自带 OpenHarmony 材料签出的 HAP；那需要经由华为开发者账号申请证书与描述文件。本地构建出的产物只能用于模拟器或 OpenHarmony 设备。

### 没有白费的部分

安卓版是完整、经过测试、可以安装的。两端共用同一套协议与同一套数据模型，所以鸿蒙版的投入并没有浪费 —— 它需要的是一个编译器层面的修复和一条签名路径，而不是推倒重来。

### 恢复开发后的下一步

- 把剩下的 ArkTS 错误类别抽成一个最小复现页面，定位根因后再逐个把功能加回去。
- 编译通过后，在 DevEco 模拟器上完整验证一遍。
- 确定鸿蒙手机的发布路径（华为 AGC 签名，还是在 OpenHarmony 设备上侧载）。

## 0.0.12 改了什么

两项键盘行为，提出需求后均已落地：

- **打开应用自动弹出系统输入法** —— 不再需要先点一下输入框。
- **发送后输入框保持可输入** —— 发完消息不会收起键盘、不会丢焦点。

其余部分一律未改动。文件格式、线协议、目录结构全部不变，因此 `0.0.12` 与 `0.0.11` 仍然完全互通 —— 与将来编译通过的鸿蒙版也一样。

## 已知限制

1. **实时聊天需要两端都装本应用。** Android 不允许第三方应用监听系统蓝牙的收件目录，所以「对方没装」时只能走上面的分享 / 导入流程，那些消息不会自动出现在对话里。
2. **必须先完成系统蓝牙配对。** 配对在系统设置里做，应用本身不实现配对流程。
3. **一次只连接一个对端。** 不支持群聊。断开后重新点对方名字即可连接。
4. **消息时间以本机写入文件的时间为准。** 两台手机时钟不一致时，排序仍然正确，但各自显示的时间戳会不同。
5. **后台通知依赖「后台接收」开关。** 关闭时应用退到后台即断开连接，自然也不会收到通知。
6. **自定义背景只影响消息区域。** 顶栏、状态行和输入栏保持主题纯色。
7. **这是文本聊天工具，不是文件传输工具** —— 单条上限 256 KB。
8. **当前安装包用口令为 `android` 的自签名调试证书签名。** 自用没问题；真要长期分发，请换成你自己的密钥。
